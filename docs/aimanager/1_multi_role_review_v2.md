## 关键硬伤

1. **ycapi-only 运行时边界不足**
   LiteLLM 完整 proxy 挂载了 provider passthrough 路由，例如 `/gemini/`、`/anthropic/`、`/bedrock/`、`/vertex_ai/`、`/openai/`、`/cohere/`、`/vllm/`、`/mistral/`、`/azure/`。这些路由可能绕过 `model_list` 与静态配置校验。v3 必须把部署层封堵或运行时禁用列为 P0。

2. **0.0 计价与预算阻断矛盾**
   v2 已意识到计价风险，但没有把非零计价作为预算、财务报表和超预算阻断的前置条件。v3 必须明确价格版本、币种、计费单位、历史快照、对账和预算阻断口径。

3. **业务管理面不足**
   v2 说保留 LiteLLM Admin UI，但总经理、财务、市场、部门管理员需要的是业务视角：成本总览、部门排行、风险事件、审批状态、报表导出、处置闭环。v3 必须把 v1 临时能力和 P1 自研门户边界讲清。

4. **非技术员工和市场流程缺口**
   v2 偏 API/开发者视角，对市场内容生产、品牌安全、外发审批、模板、非技术入口不足。v3 必须定义市场试点前置要求和场景标签字典。

5. **验收标准不可执行**
   v2 的 AC 过粗，缺 passthrough 封堵、非零计价、mock/live、错误契约、RBAC、报表、市场流程、合规留存等验收。v3 必须扩展为可测试矩阵。

## 终审结论

PRD v2 不直接进入实现。PRD v3 作为修订版进入 M0 复评基线；M1 本地技术验证可在完成 P0 技术验收项后启动，M2 业务试点必须先补齐经营、财务、合规、市场和 UI 的前置条件。
